# D1 (SQLite) {#d1-sqlite}

[Cloudflare D1](https://developers.cloudflare.com/d1/) 是 Void 默认使用的 SQLite 数据库。从定义 [schema](/zh/guide/database#schema-definition) 开始，Void 会在本地开发和部署时管理数据库。

## 本地数据库 {#local-database}

开发服务器与本地 `void db` 命令共用同一个数据库。如果 `void.config.ts` 中的 `cloudflare.d1_databases` 声明了 D1 绑定，Void 会使用该绑定的 ID。本地开发时，`preview_database_id` 的优先级更高。

如果希望将本地数据存放在 `.void` 之外，在 Vite 配置中设置 `voidPlugin({ persistTo: 'local-state' })`。运行数据库命令前，先启动一次开发服务器，让 Void 记录该目录。修改 Vite 配置后，需要再次启动开发服务器以更新目录记录。自行管理 Cloudflare 运行时的框架使用 `.wrangler/state`。

## 迁移与原型开发 {#migrations-prototyping}

使用 `void db push` 可以在本地应用 schema 变更，不生成迁移文件。部署前，请生成并提交迁移：

```sh
void db generate
void db migrate # apply locally
void deploy     # apply remotely and deploy
```

完整流程请参阅[数据库命令](/zh/reference/cli/database#database)。

## 批量操作 {#batch-operations}

D1 支持在一次请求往返中批量执行多条语句：

```ts
import { users, posts } from '@schema';
import { db, eq } from 'void/db';

await db.batch([
  db.delete(posts).where(eq(posts.userId, userId)),
  db.delete(users).where(eq(users.id, userId)),
]);
```

## 读副本 {#read-replication}

Void 创建数据库时，会启用 [D1 读副本](https://developers.cloudflare.com/d1/best-practices/read-replication/)。要为已有数据库启用此功能，运行 `void deploy --platform cloudflare --provision`。通过 `void/db` 导出的 `db` 查询时，每个 Void 请求都会使用独立的 D1 会话，让读取可以在靠近请求的位置执行；同一请求内，后续查询看到的数据不会比先前查询更旧。没有 Void 请求作用域的框架处理函数，会让每次数据库操作都从主数据库开始。`createDb` 会为传入的绑定创建支持使用读副本的会话。

不同请求之间，副本数据可能存在复制延迟。身份验证会话检查从主数据库开始，因此不会因副本延迟而接受已撤销的会话。如果其他读取也必须从主数据库的最新数据开始，请使用 `cloudflare:workers` 导出的绑定调用 `env.DB.withSession('first-primary')`。其他查询库和原生 D1 调用需要自行使用 `withSession()` 才能利用读副本；直接使用不带会话的 D1 绑定时，会从主数据库读取。

## 其他查询层 {#alternative-query-layers}

使用 `cloudflare:workers` 导出的 `env.DB`，可以配合其他查询库或直接调用原生 D1 API：

### Kysely {#kysely}

```ts
import { env } from 'cloudflare:workers';
import { Kysely } from 'kysely';
import { D1Dialect } from 'kysely-d1';

const db = new Kysely<Database>({ dialect: new D1Dialect({ database: env.DB }) });
```

### 原生 D1 API {#raw-d1}

```ts
import { env } from 'cloudflare:workers';

const { results } = await env.DB.prepare('SELECT * FROM users WHERE id = ?').bind(userId).all();
```

无论使用哪种查询层，Void 都会继续负责绑定推断和部署。

::: warning ⚠️ 元框架限制
Nuxt 和 SvelteKit 2 在本地开发时不支持从 `cloudflare:workers` 导入。请使用 `void/db`，或框架提供的绑定访问 API。SvelteKit 3 支持这类导入。
:::
