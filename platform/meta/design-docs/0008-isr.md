# Incremental static regeneration

Void caches eligible rendered responses at the edge and in `ISR_CACHE` KV, with entries keyed by deployment. A fresh edge entry returns immediately. On a miss, dispatch uses the stored render when it is fresh, or invokes the Worker to render and repopulate the cache. Stale responses may be served while revalidation runs in the background. Deployments have separate cache keys, so a new version does not reuse an old render.

Applications configure route TTLs and can request on-demand revalidation. Cache keys account for routing and rewrite variants. See the [ISR implementation](../../../packages/isr), [dispatch](../../../platform/packages/dispatch/src/index.ts), and [revalidation guide](../../../docs/en/guide/edge/revalidation.md).
