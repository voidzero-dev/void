# Incremental static regeneration

Void caches eligible rendered responses at the edge and in persistent storage.
A fresh edge entry returns immediately. On a miss, the runtime uses a fresh
stored render or invokes the application to render and repopulate the cache.
Stale responses may be served while revalidation runs in the background.

Native Cloudflare deployments use an `ISR_CACHE` KV namespace. Managed platform
deployments use the existing assets R2 bucket under `isr-cache/`. R2 is
authoritative for managed reads and writes: falling back to eventually
consistent KV after a purge could restore deleted HTML for its original TTL.
Legacy platform KV entries participate only in purge and cleanup.

Stored entries retain response status, headers and body, with creation time,
TTL and cache policy metadata. Keys scope renders to the deployment, host and
path, including routing and rewrite variants. A new deployment cannot reuse a
previous version's render. Applications configure route TTLs and request
on-demand revalidation, which removes persistent entries and purges edge variants.
Cache misses and failed reads fall back to rendering.
