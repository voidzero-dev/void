# Connected apps and publish approval

Replace the companion callback allowlist from b829c7f7f with registered confidential OAuth clients. A client's callback origin is not an authority to receive a full API session.

Clients have exact callbacks, a hashed secret, an administrator-selected maximum scope, and an enabled flag. Profile authorization codes require explicit Void consent, S256 PKCE, client authentication, and exact callback binding. Codes are hashed, expire in five minutes, and are consumed transactionally. Profile access tokens are opaque, hashed in PostgreSQL, expire within an hour, and expose only subject and username. The code exchange also issues an opaque, hashed refresh token. Each redemption rotates it and issues a new access token on the same grant; the new token keeps the family expiry, which is the expiry of the grant's login session. A rejected redemption rolls back and leaves the token usable. Redeeming a rotated-out token revokes the grant. Publish tokens never get a refresh token.

Void's existing human login flow can redirect only to its own OAuth login callback. That bridge exchanges the existing PKCE code on Void and retains the API token in a Void-only HttpOnly cookie. External applications never receive that token. State and browser proof bind consent; forms require the configured Void origin. OAuth responses are uncached and suppress referrers.

A publish request commits to canonical SHA-256 of the manifest, asset manifest, and every Worker module. PostgreSQL retains metadata and digest, not executable bytes. The consent page identifies the registered operator, project, client-reported checkpoint label, resources, manifest, and digest. Approving a new project calls the existing project creation service so admission, slug rules, plans, and installation locks stay intact. Approval for an existing project requires ownership.

The code exchange issues a fifteen-minute JWT with a new oauth-deploy audience, project, and approval UUID. Older platform runtimes reject that audience. Authentication default-denies endpoints; uploads must match declared hashes and sizes, deployment must match the digest, and its idempotency key must equal the approval UUID. Deployment Queue receipts enforce one execution with recoverable retries. Platforms without that Queue fail closed.

Grants retain the upstream human session and its Access identity attested during browser consent. Every use checks user suspension, session revocation and expiration, provider enabled/generation, current Access settings, and client/grant status. Queued execution rechecks these and project ownership before cutover; share locks fence client, grant, identity, and provider mutations during that transaction. Lock order follows configuration → client → grant → user → connection → session → approval. A refresh takes the grant FOR UPDATE in that chain, so refreshes of one grant run in turn, and locks its refresh-token row last: grant → token, the same order as the cascade when a grant is deleted. Client disablement takes its client lock before grants and requests. OAuth service endpoints accept an admitted Access service identity, then independently validate purpose-bound credentials. Browser consent never bypasses the human Access gate.

Vibevoid stores only an encrypted profile token in its session and revalidates it before workspace access. Old account-token session cookies are not recognized. Logout revokes the grant. A separate sandbox builds an immutable checkpoint without platform credentials, stores its prepared output privately in R2, and is destroyed before Void approval. After callback, the server sends only approved bytes with the one-publish token; no platform token enters project code, the editing sandbox, or the publishing sandbox.

Registration and disablement use the existing admin auth, CSRF and durable intent/outcome audit. User revocation is restricted to the current subject's grants. Hourly housekeeping deletes expired requests and grants in bounded batches after a one-day retention window. `oauth_grants.expires_at` is only the access token expiry, so a grant that is not revoked is kept while its refresh token family is live, and the connections page lists it. The SQL migration adds tables and indexes only; native Cloudflare deployments gain no resource bindings.

Trust remains explicit: registering a client does not attest its generated code. Approved code has the target project's runtime secrets and resources. Approval cannot prove that an operator's checkpoint label describes the submitted artifact. Cancellation or revocation does not undo code already published. OpenID Connect is not implemented.

OAuth asset PUTs sign If-None-Match: * and expire within the publish token lifetime. Existing objects produce 412; deployment streams every approved asset through BLAKE3 before provisioning or cutover. This prevents a client from substituting bytes with a matching MD5 or overwriting verified content through its upload URLs. Browser consent forms use same-origin referrers so Chrome retains a verifiable Origin; code redirects keep no-referrer. Wrangler’s localhost port rewrite is accepted only in explicit development bypass mode.
